About Us

Multi-Resource Detection

Specialized scanners (Ec2Scanner, RdsScanner, EbsScanner, ElbScanner) continuously evaluate utilization metrics via native AWS SDK v2 integration.

Policy & Remediation Engine

Flexible IdlePolicy rules evaluate candidates before passing them to the RemediationEngine for action enforcement or Slack reporting.

Serverless Architecture

Packaged with Docker and deployed to AWS Lambda via Terraform, enabling zero-idle-cost execution driven by GitHub Actions CI/CD.

Application Workflow

Step 01: Invocation GreenOpsHandler.java

Lambda Trigger & Config Load

AWS Lambda entry point initializes application configurations via AppConfig using environment variables or Systems Manager parameters.

Step 02: Resource Discovery ResourceScanner implementations

Target Resource Scanning

Execution spreads across scanner instances leveraging AwsClients to fetch active EC2, RDS, EBS, and ELB resource instances.

Step 03: Policy Evaluation DefaultIdlePolicy.java

Idle Candidate Filtering

Discovered resources are processed through policy rules configured in application.yml to identify non-utilized capacity.

Step 04: Financial Assessment PricingCostEstimator.java

Savings Projection

Identified idle candidates are passed to CostEstimator to calculate projected monthly and annualized cost reductions.

Step 05: Action & Reporting RemediationEngine & SlackNotifier

Remediation & Notification

The ActionExecutor handles optional resource state changes, while SlackNotifier constructs structured block updates to report back to your team.

How It Works

1. Lambda Entry Point

GreenOpsHandler serves as the main AWS Lambda interface, handling incoming execution events and routing workflow contexts.

2. AWS SDK v2 Integration

AwsClients acts as a centralized factory, issuing thread-safe AWS SDK v2 clients optimized for serverless execution runtimes.

3. Pluggable Resource Scanners

Modular scanners implement the core ResourceScanner interface, enabling simple extension to support new AWS service types.

4. Modular Idle Policies

Evaluation thresholds are abstracted into IdlePolicy implementations, separating utilization business logic from data collection.

5. Containerized Build

The Java project compiles via Maven into a runtime container image defined in Dockerfile for consistent Lambda container deployments.

6. Terraform Infrastructure

Infrastructure resources (IAM roles, Lambda configuration, schedules) are managed as code in the terraform/ directory and deployed via .github/workflows/deploy.yml.
